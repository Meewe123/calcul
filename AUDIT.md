# Аудит проекта calcul

Дата: 2 октября 2026.
Что проверялось: ветка `main` (README и файл с заметками) и ветка `claude/simple-calculator-8o3g11` из [PR #1](https://github.com/Meewe123/calcul/pull/1), где лежит сам калькулятор — один файл `index.html` на 212 строк.

Как проверялось:

- прочитан весь код;
- калькулятор запущен в Chromium через Playwright, сценарии прогнаны с клавиатуры и мышью;
- доступность проверена axe-core и вручную посчитан контраст цветов;
- Lighthouse (мобильный профиль) — для отправной точки.

Все баги ниже воспроизведены, а не предположены.

## Коротко

Это рабочий калькулятор на четыре действия, внешне — копия калькулятора iPhone (тёмный корпус, оранжевые клавиши операций). Код аккуратный и читается легко, но в нём есть ошибка, из-за которой калькулятор **выдаёт неверные ответы** на длинных числах. На телефоне нельзя исправить опечатку, а длинное число обрезается и не видно, что вводишь. Тестов, сборки, CI, лицензии и нормального README нет. Как проект для портфолио он сейчас не отличим от сотен похожих.

## Что хорошо

- Ноль зависимостей: открыл файл — работает. Для такого продукта это правильно.
- Логика компактная и понятная: состояние в четырёх переменных, функции названы по смыслу.
- Есть управление с клавиатуры, включая `Backspace` и `Esc`.
- `Enter` вызывает `preventDefault`, поэтому кнопка в фокусе не нажимается второй раз — это частая ошибка, и здесь её нет.
- Деление на ноль не роняет страницу, а показывает «Ошибка».
- Десятичная запятая вместо точки — уважение к русской локали.
- Lighthouse: производительность 100, доступность 96, лучшие практики 96, SEO 90 — база хорошая, потому что страница крошечная.

## Доступность

- **Контраст.** Белый текст на оранжевых клавишах `#f09a2a` — **2,24 : 1** при норме WCAG 4,5 : 1. axe этого не замечает, потому что на клавишах только символы (÷ × − + =), но для людей правило то же. Граница обычной клавиши с корпусом — 1,27 : 1.
- **Скринридер ничего не слышит.** Нет `aria-live`: после `=` результат не объявляется. У клавиш нет `aria-label`: «C» и «±» читаются как буквы и знаки, а не как «Сбросить» и «Сменить знак».
- **Структура.** Нет `<main>`, нет заголовка `h1`, контент вне ориентиров (axe: `landmark-one-main`, `page-has-heading-one`, `region`).
- **Ввод с клавиатуры не виден на экране:** клавиши не подсвечиваются, когда цифру печатаешь, а не нажимаешь мышью.
- Нет `touch-action: manipulation`: на iOS быстрый двойной тап по клавише может приблизить страницу.

## Дизайн

- Это узнаваемая копия калькулятора iOS: тёмный корпус, серые клавиши, оранжевый столбец операций. Своего характера нет — именно такой результат комиссия видела сотни раз.
- Системный шрифт по умолчанию; цифры не табличные, поэтому при вводе число «прыгает».
- Нет дизайн-системы: цвета, размеры и отступы записаны прямо в правилах, без переменных.
- Одинаковое скругление 10 px у всех клавиш и дисплея, тень «на всякий случай».
- Нет светлой темы и не учитывается системная настройка.
- Нет иконки, заголовок вкладки — просто «Калькулятор».
- Нет истории вычислений: результат пропадает при следующем вводе.

## Тексты

- README из трёх разделов: нет описания, скриншота, ссылки на демо, стека.
- В интерфейсе единственный текст — «Ошибка». Он не говорит, что случилось и что делать.

## Код и архитектура

- Логика вычислений перемешана с работой с DOM внутри одного `<script>`, поэтому её нельзя протестировать отдельно.
- Ошибка хранится как строка `'Ошибка'` в той же переменной, что и число. Из-за этого почти каждая функция начинается с проверки `current === 'Ошибка'`. Это хрупко: опечатка в одной проверке — и ломается весь сценарий.
- Модель «ввёл число — нажал операцию» не умеет скобки и приоритет операций: `2 + 3 × 4` считается как `(2 + 3) × 4 = 20` при пошаговом вводе.
- Нет тестов, линтера, форматтера, проверки типов.

## Инфраструктура и безопасность

- Нет `package.json`, сборки, CI, деплоя. Демо нигде не опубликовано.
- Нет `LICENSE` — формально код нельзя использовать.
- Секретов в репозитории нет (и они проекту не нужны) — это хорошо.
- Нет Content Security Policy; для статической страницы её легко добавить через `<meta>`.
- В корне `main` лежит файл с фрагментом промпта (`## Дизайн убрать «ИИ-стиль».txt`) — в портфолио он выглядит как мусор.
- Сам калькулятор не влит в `main`: [PR #1](https://github.com/Meewe123/calcul/pull/1) открыт, а на главной странице репозитория только README из одного слова.

## Что не нужно делать

- Тащить React или другой фреймворк ради 20 кнопок: это ухудшит скорость и ничего не даст.
- Добавлять инженерные функции (синусы, степени, графики): цель — цельный продукт, а не список функций.
- Делать сервис-воркер для офлайна: он легко начинает отдавать старую версию после обновления, а выигрыш для калькулятора небольшой.
- Выдумывать отзывы, счётчики пользователей и логотипы.

## План работ

Выполняется по порядку, каждый шаг — отдельные коммиты.

1. Убрать файл с промптом, настроить инструменты: Vite, TypeScript, ESLint, Prettier, Vitest.
2. Ядро без DOM: точная десятичная арифметика на `BigInt`, разбор выражений (рекурсивный спуск), правила процентов, форматирование чисел для RU и EN, редактор выражения, состояние калькулятора с лентой. Всё покрыть модульными тестами, арифметику — ещё и тестами на свойства.
3. Интерфейс: дизайн-система в CSS-переменных, дисплей, клавиатура, лента с сохранением и отменой очистки, пустое состояние с примерами, две темы, два языка, справка по клавишам.
4. Доступность и детали: `aria-live`, подписи, фокус, подсветка клавиш, `prefers-reduced-motion`, страница 404.
5. SEO, Open Graph, иконки, CSP.
6. Сквозные тесты в браузере (Playwright + axe), GitHub Actions: проверки, Lighthouse, публикация на GitHub Pages, Dependabot.
7. README на двух языках со скриншотами и схемой, описание дизайн-системы, LICENSE, CHANGELOG.
8. REPORT.md: что сделано и что осталось сделать руками.
